# 名片认证与模板授权 V2 规格

## 目标

重构员工名片、企业认证和模板授权，使账号可以没有名片，并满足以下规则：

- 微信首次注册只创建账号，不创建默认名片。
- 总公司和所有子公司都必须先完成企业认证，没有任何默认企业归属。
- 总部管理员可以管理所有企业、模板、账号和名片。
- 企业管理员只能使用总部明确发放给本企业的名片模板；没有授权模板时不能创建或导入名片。
- 员工只能使用“已认证企业”和“企业已获授权模板”的交集创建名片。
- 取消企业认证时归档该企业名片；收回模板授权只阻止继续创建，不影响已有有效名片。
- 存量公开名片默认保持可用，迁移过程不得批量破坏既有分享链接。

## 核心模型

### 员工与 OCR

- `kind: employee` 使用 `cards[]` 多名片模型，允许 `cards=[]`。
- `kind: ocr` 是名片夹中的独立联系人，使用顶层字段和独立投影，不复用员工 `cards[]`。

### 企业归属

- `companyId: ''`：未归属企业。
- `companyId: 'default'`：总公司。
- 其他值：对应子公司。
- 新逻辑禁止用 `companyId || 'default'` 推断名片归属。

### 名片生命周期

- `lifecycle: draft`：尚未满足公开条件。
- `lifecycle: active`：可以公开和分享。
- `lifecycle: archived`：保留历史数据但不可公开。
- 账号状态继续使用 `person.status`，不得与名片生命周期混用。

### 认证

- 认证唯一键为 `personId + companyId`。
- 总公司也需要认证。
- 认证不依赖 `cardId`，兼容期内旧客户端传入的 `cardId` 可忽略。
- PostgreSQL 使用独立的 `company_certifications` 表，保留旧表用于兼容迁移。

### 模板授权

- 名片模板授权唯一键为 `templateId + companyId`。
- 总部管理员管理授权。
- 企业管理员和员工均不能通过修改 `companyId` 绕过模板授权。
- 公司品牌页面模板 `classic/ink/light` 与名片模板 `classic/horizon/wave/tpl-*` 保持独立。

## API 契约

- `GET /api/employee/me` 在零名片时返回 `cards: []`、`activeCardId: ''`。
- `GET /api/employee/certification` 不要求 `cardId`。
- `POST /api/employee/certification` 接受 `{ companyId }` 或 `{ code }`。
- `GET /api/employee/templates` 只返回员工已认证企业获得的模板。
- `POST /api/employee/cards` 必须同时校验认证与模板授权。
- 无真实有效名片的公开访问返回 `NO_ACTIVE_CARD`。
- 账号停用继续返回 `CARD_UNAVAILABLE` 或 `ACCOUNT_INACTIVE`。
- 归档名片返回 `CARD_ARCHIVED`。

## 公开可见性

所有员工名片公开入口统一调用同一个解析函数，包括：

- 公开名片详情
- 二维码
- 浏览量写入
- 名片夹收藏和读取
- 指定 `shareCard` 的分享链接

## 删除与撤销

- 子公司管理员删除员工等价于归档本公司名片并撤销本公司认证，不删除账号和浏览历史。
- 总部永久删除保留为明确的总部操作。
- 归档或删除当前名片后必须重算 `activeCardId`。

## 兼容与迁移

- 存量真实名片回填 `lifecycle: active`。
- 无法可靠追溯来源的存量卡标记 `source: legacy_unknown`，不使用启发式自动下架。
- 现有自定义模板 `companyIds` 转换为授权记录。
- 不自动给所有企业补发内置模板。
- 新版小程序支持零名片并发布后，才关闭后端默认建卡行为。

## 测试要求

- 每个实施切片完成后运行相关测试和完整后端测试。
- 覆盖零名片、OCR、公开可见性、总部认证、子公司认证、模板授权、撤销归档、活动名片重算和旧客户端兼容。
- 保留总部永久删除测试；新增子管理员归档语义测试。

## 完成标准

- 新微信账号没有默认名片和默认企业。
- 用户认证任一企业前看不到可用模板。
- 企业没有总部发放模板时，管理员和员工都不能创建该企业名片。
- 所有企业包括总公司都走认证审核。
- 总管理员可以查看和管理全部账号与名片。
- OCR 名片夹、存量公开链接和历史浏览数据不因模型迁移丢失。
- 自动化测试全部通过，并完成服务器部署后的健康检查。
